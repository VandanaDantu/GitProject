What is Spring JDBC?

JDBC is Java's standard API for working with relational databases. Spring JDBC is part of the Spring Framework: it keeps you in control of SQL while removing repetitive connection, statement, and result-set handling. Its central helper, JdbcTemplate, runs SQL and coordinates this routine work.

Why use it instead of traditional JDBC?

With traditional JDBC, application code commonly opens a connection, creates a statement, binds values, processes a ResultSet, closes each resource, and handles low-level SQLException errors. Repeating this boilerplate code makes code longer and resource leaks easier. Spring JDBC reduces that work and simplifies connection management and resource cleanup.

JdbcTemplate manages these routine steps, including resource cleanup. You still write SQL and choose how query results map to Java objects. Spring also translates many database errors into its consistent unchecked DataAccessException hierarchy instead of requiring every caller to handle SQLException.

DataSource and database connectivity

A DataSource provides database connections. It represents the database connectivity settings and commonly obtains connections from a connection pool. The database URL, JDBC driver, credentials, and target database vendor must be configured for your environment. A JDBC driver translates JDBC calls for a particular database.

Spring configures a DataSource as a bean and injects it into JdbcTemplate. A repository can then receive the template through constructor injection; @Autowired is another way to mark a dependency injection point. Spring's application context creates these beans and connects them without the repository constructing its own database infrastructure.

@Repository
public class BookRepository {
    private final JdbcTemplate jdbcTemplate;

    public BookRepository(JdbcTemplate jdbcTemplate) {
        this.jdbcTemplate = jdbcTemplate;
    }
}

In an application, define the DataSource and a JdbcTemplate bean in configuration, or use Spring Boot's database configuration. Never hard-code production credentials in source code.

Prepared statements and safe parameters

Use a prepared statement (the JDBC PreparedStatement, also called a parameterized query) to pass values separately from SQL text. This helps prevent SQL injection and handles values using the JDBC driver. Do not concatenate user input into SQL.

String sql = "select id, title from books where id = ?";
Book book = jdbcTemplate.queryForObject(
    sql,
    (resultSet, rowNumber) -> new Book(
        resultSet.getLong("id"),
        resultSet.getString("title")),
    bookId
);

The question mark is a query parameter. With positional query parameters, the values supplied to JdbcTemplate match the question marks in order. Named parameters give values readable names instead; NamedParameterJdbcTemplate supports that style. In either case, JdbcTemplate binds values separately from the SQL text.

RowMapper and query methods

A RowMapper converts one row of a ResultSet into a Java object. It keeps row mapping separate from query execution and is called for each row returned.

  • query() executes a select that can return zero or more rows, usually mapped into a list.
  • queryForObject() reads one expected result, such as one row or one scalar value. It reports an error if the result does not match expectations.
  • update() executes an insert, update, or delete and returns the number of affected rows.
RowMapper<Book> mapper = (rs, row) ->
    new Book(rs.getLong("id"), rs.getString("title"));

List<Book> books = jdbcTemplate.query(
    "select id, title from books", mapper);

Integer count = jdbcTemplate.queryForObject(
    "select count(*) from books", Integer.class);

CRUD examples

CRUD means create, read, update, and delete. These examples use placeholders and parameters rather than joining input into the SQL string.

// Create: insert a row
int inserted = jdbcTemplate.update(
    "insert into books (title) values (?)", title);

// Read: select rows and map each row
List<Book> books = jdbcTemplate.query(
    "select id, title from books where title = ?",
    mapper, title);

// Update: change a row
int changed = jdbcTemplate.update(
    "update books set title = ? where id = ?", title, id);

// Delete: remove a row
int deleted = jdbcTemplate.update(
    "delete from books where id = ?", id);

The returned affected-row count can help the application check whether an insert, update, or delete changed the expected number of rows. An update operation is one common use of the update() method.

Exceptions, transactions, and trade-offs

Spring JDBC translates many SQL errors into DataAccessException, a common unchecked exception type. Handle it where the application can recover or report a useful failure; do not silently pretend a failed database operation succeeded.

A transaction groups operations into one unit of work. A transaction boundary defines which operations succeed together: the application commits when all work succeeds and rolls back when a failure occurs. Transaction management can be configured declaratively or in application code. Spring manages the commit and rollback behavior through the PlatformTransactionManager interface and a transaction manager such as JdbcTransactionManager or DataSourceTransactionManager.

  • Benefits: less JDBC boilerplate, consistent exception translation, easy dependency injection, and direct control over SQL.
  • Limitations: you still design SQL and schemas, map rows, and manage transaction boundaries. It does not provide the object-relational mapping of an ORM.

For larger or repeated workloads, Spring JDBC also supports batch update operations. Select the tool that fits your data access needs and keep connections, credentials, and transactions configured for the deployment environment.
