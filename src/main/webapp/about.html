What is Hibernate?

Hibernate is a Java object-relational mapping (ORM) framework. It helps an object-oriented Java application store, retrieve, update, and delete data in a relational database. Instead of writing JDBC code for every operation, developers map Java classes and objects to database tables and rows.

What does ORM mean?

ORM means object-relational mapping. A Java object represents a row, a Java class represents a database table, and an object's fields map to table columns. This mapping lets an application work with familiar Java objects while Hibernate handles much of the SQL and database connectivity. Data persistence is the process of keeping application data in durable storage such as a relational database.

Why use Hibernate?

  • It reduces repetitive JDBC connection, statement, and result-set handling.
  • It maps Java classes to relational database tables and supports data persistence.
  • It provides transaction management, caching, and object-oriented query options.
  • Its dialect support can help an application work with different relational databases.

Hibernate architecture

A typical application configures Hibernate for a database, creates one SessionFactory, and opens a short-lived Session when it needs to work with persistent objects.

  1. Configuration: reads database connectivity settings, mappings, and the database dialect.
  2. SessionFactory: a heavyweight, thread-safe factory, normally created once for an application.
  3. Session: a short-lived unit of work used to load or persist objects; it also holds the first-level cache.
  4. Transaction: groups related changes so they can be committed together or rolled back on failure.
  5. Database: stores the relational tables and their rows.

Close each Session after use. A Session is not intended to be shared between threads. This lifecycle is often called Session management.

Entities, classes, and tables

An entity class is a Java class that Hibernate maps to a database table. Each entity object corresponds to a row, and its fields correspond to columns. A primary key uniquely identifies each row.

An annotation makes a mapping instruction visible in the Java class. Hibernate uses annotations such as:

  • @Entity marks a class as a persistent entity.
  • @Table optionally selects the database table name.
  • @Id identifies the primary key field.
  • @GeneratedValue asks Hibernate to use a configured strategy to generate key values.
import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import jakarta.persistence.Table;

@Entity
@Table(name = "students")
public class Student {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String name;

    protected Student() { }

    public Student(String name) {
        this.name = name;
    }
}

The example uses Jakarta Persistence annotations, as used by modern Hibernate versions. An entity normally also has a no-argument constructor and suitable accessors.

Configuration and database connectivity

Hibernate needs a database connection, a dialect that describes the database's SQL variations, and mapping information for the entity classes. These settings can be supplied through Java configuration or a configuration file such as hibernate.cfg.xml.

<hibernate-configuration>
  <session-factory>
    <property name="hibernate.connection.driver_class">org.postgresql.Driver</property>
    <property name="hibernate.connection.url">jdbc:postgresql://localhost:5432/school</property>
    <property name="hibernate.connection.username">app_user</property>
    <property name="hibernate.connection.password">change_me</property>
    <property name="hibernate.dialect">org.hibernate.dialect.PostgreSQLDialect</property>
    <mapping class="example.Student"/>
  </session-factory>
</hibernate-configuration>

Use environment-specific configuration and a securely managed password in a real application; the sample values above are illustrative. A JDBC driver and a reachable database are also required to run a Hibernate application. This learning assessment itself does not connect to a database.

Session, transactions, and CRUD

CRUD stands for create, read, update, and delete. Hibernate offers methods for these operations; each change should be made in a transaction so the application can commit successful work or roll back incomplete work.

try (Session session = sessionFactory.openSession()) {
    Transaction transaction = session.beginTransaction();
    try {
        Student student = new Student("Asha");
        session.persist(student);                  // insert
        Student found = session.find(Student.class, student.getId()); // select
        found.setName("Asha Kumar");               // update
        transaction.commit();
    } catch (RuntimeException exception) {
        transaction.rollback();
        throw exception;
    }
}

In a real application, keep transaction boundaries around the complete unit of work and ensure a rollback occurs if an operation fails. Hibernate can also delete an entity with session.remove(entity).

HQL and queries

Hibernate Query Language (HQL) is an object-oriented query language. It refers to entity classes and their properties rather than directly naming database tables and columns. Hibernate translates an HQL query into database-specific SQL using the configured dialect.

List<Student> students = session
    .createQuery("from Student where name = :studentName", Student.class)
    .setParameter("studentName", "Asha")
    .getResultList();

Use parameters rather than joining user input into query text. HQL is useful for entity queries; native SQL is also available when needed.

Mapping relationships

Relationship annotations describe how entity classes relate. Choose the relationship that matches the data model and configure the owning side and foreign key carefully.

  • One-to-one: one record is associated with one record, such as a person and a single profile.
  • One-to-many: one parent is associated with multiple children, such as a department and employees.
  • Many-to-one: several records refer to one parent, such as many employees belonging to one department.
  • Many-to-many: many records on either side can be associated, such as students and courses, usually through a join table.

A mapping relationship describes how related entity classes connect. In relational databases, these mappings are implemented with foreign keys and, for many-to-many relationships, a join table.

Loading and caching

Lazy loading postpones loading related data until it is accessed. Eager loading loads the related data as part of the initial operation. Lazy loading can avoid unnecessary work, but accessing unloaded data after its Session is closed can fail. Eager loading can retrieve more data than needed, so use it thoughtfully.

The first-level cache belongs to a Session and is enabled by default: repeated loads of the same entity in one Session can reuse the managed object. The optional second-level cache is shared across Sessions for a SessionFactory when explicitly configured with a compatible cache provider. Caching can improve performance, but requires a suitable freshness and invalidation strategy.

Advantages and limitations

Advantages

  • Less repetitive JDBC and mapping code for common persistence work.
  • Object-oriented access to relational data, transactions, and HQL queries.
  • Dialect and mapping support for a range of relational databases.

Limitations to understand

  • There is a learning curve, and incorrect mappings or loading choices can hurt performance.
  • Generated SQL may need inspection; complex reports may be clearer with native SQL.
  • It does not remove the need to understand database design, transactions, or connectivity.
