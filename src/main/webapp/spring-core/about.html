Spring Framework and Spring Core

The Spring Framework is a collection of tools for building Java applications. Spring Core is its foundation: it creates and connects application objects and helps keep classes focused on their own work.

For example, a notification service can depend on a message sender interface instead of creating a particular email sender itself. That makes it easier to change or test the sender later.

IoC and Dependency Injection

Inversion of Control (IoC) means the application gives Spring responsibility for creating and connecting many objects, rather than each class constructing all of its own dependencies. Dependency Injection (DI) is the technique Spring uses to provide an object with the other objects it needs.

In plain Java, a service might construct its dependency directly:

MessageSender sender = new EmailMessageSender();
NotificationService service = new NotificationService(sender);

With DI, Spring creates the sender and supplies it to the service. The service can depend on an interface, which encourages loose coupling instead of tight coupling to one implementation.

Beans and the Spring IoC container

A Spring bean is an object created, configured, and managed by Spring. The Spring IoC container reads configuration, creates beans, injects their dependencies, and manages their lifecycles.

BeanFactory is the basic container interface and provides bean creation and dependency injection. ApplicationContext builds on it with commonly used application features such as events, resource loading, and easier integration. Most application code uses an ApplicationContext.

For example, asking the container for a bean with getBean returns an object that Spring manages. The container can also build the bean graph when the application starts.

XML-based configuration

Spring can describe beans and their relationships in an XML configuration file. The file can be placed on the application's classpath so the container can load it during context refresh. In this example, the container creates the sender first and injects it into the service through a constructor argument:

<beans xmlns="http://www.springframework.org/schema/beans">
  <bean id="emailSender" class="example.EmailMessageSender" />
  <bean id="notificationService" class="example.NotificationService">
    <constructor-arg ref="emailSender" />
  </bean>
</beans>

XML is one configuration option. Spring also supports Java configuration and component scanning.

Constructor and setter injection

Constructor injection passes required dependencies when the bean is created. It makes required dependencies clear and allows fields to be final.

public NotificationService(MessageSender sender) {
    this.sender = sender;
}

Setter injection provides a dependency through a setter method after construction. It can suit optional or changeable dependencies.

public void setMessageSender(MessageSender sender) {
    this.sender = sender;
}

In XML, constructor injection commonly uses <constructor-arg>; setter injection uses <property>. Choose the approach that communicates whether a dependency is required or optional.

Autowiring and annotations

Autowiring lets Spring find and supply a matching dependency. In annotation-based configuration, @Autowired marks an injection point. @Component identifies a class Spring may discover, @ComponentScan tells Spring where to search, and @Configuration plus @Bean define beans in Java configuration. @Value can inject a configured value.

@Component
public class NotificationService {
    private final MessageSender sender;

    @Autowired
    public NotificationService(MessageSender sender) {
        this.sender = sender;
    }
}

When more than one bean matches a dependency, configuration must identify the intended bean. Constructor injection makes such dependencies easy to see.

Bean scopes

A bean scope controls how many instances Spring creates and how long they are available.

ScopeMeaning
singletonOne bean instance per bean definition in a Spring container; this is the default.
prototypeA new instance is created whenever the container is asked for that bean.
request scopeOne instance for a single web request.
session scopeOne instance for a web session.
application scopeOne instance for a web application context.
websocket scopeOne instance for a WebSocket session.

Request, session, application, and websocket scopes are web-aware scopes. They require a web application context.

The bean lifecycle

A typical bean lifecycle starts when the container reads configuration and creates the object. Spring injects dependencies, may call aware interfaces, and can pass the bean through a BeanPostProcessor before and after initialization. It then makes the bean ready for use. When the container shuts down, it can run destruction callbacks.

  1. Object creation and object wiring: Spring constructs the bean and supplies its dependencies.
  2. Initialization: custom setup can run through an init method, InitializingBean, or a post-processor.
  3. Use: application code works with the fully initialized bean.
  4. Destruction: a destroy method or DisposableBean callback can release resources when the context closes.

XML can name these callbacks with init-method and destroy-method. Lazy initialization delays creation until a bean is first requested; eager initialization creates singleton beans while the context is refreshed. The exact callback behavior depends on the bean scope.
